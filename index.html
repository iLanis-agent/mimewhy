One line of header. A dozen silent rules.

Content-Type: Text/HTML; Charset="utf-8" looks simple. It is not. MimeWhy decodes any media type and explains the rules that bite: case folding, the text/* charset trap, multipart boundary quoting, and what vnd. and +json actually promise.

The charset trap

A text/* type with no charset means receivers guess the encoding - old HTTP said ISO-8859-1, modern stacks assume UTF-8, and mojibake is born in the gap. But put a charset on an image and it is meaningless: bytes, not characters.

Suffixes and trees are real metadata

application/vnd.api+json tells you three things: a vendor owns it (vnd.), it is JSON underneath (+json, so generic JSON tooling applies), and none of that makes it a standard. The prefix and suffix are parseable, registered structure.

Multipart is a quoting test

The boundary parameter must be quoted if it contains specials, must never appear in the content, and its closing delimiter grows a trailing --. Most multipart bugs are boundary bugs.
